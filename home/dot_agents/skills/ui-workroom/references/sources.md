# Find a useful reference

Start with interfaces that solve the same user task.
Compare content density, hierarchy, alignment, and interaction feedback rather than copying a page's surface style.

Use these sources when the brief has no references.

- [Dembrandt skills](https://www.dembrandt.com/skills) covers design tokens, hierarchy, interaction states, and repeated component alignment.
- [AI UX Playground](https://aiuxplayground.com/skills/for-designers) indexes design, accessibility, typography, motion, and critique skills.
- [Better Layout](https://aiuxplayground.com/skills/better-layout) emphasizes shared edges, grouping, and layouts that survive content growth.
- [Design Engineering](https://aiuxplayground.com/skills/emil-design-eng) connects motion choices to interaction frequency and purpose.
- [Break UI](https://aiuxplayground.com/skills/break-ui) tests realistic worst-case data through the normal data boundary.
- [Better Typography](https://aiuxplayground.com/skills/better-typography) checks reading comfort, text growth, wrapping, and recoverable truncation.

For React components, inspect a matching implementation rather than importing an entire library.

- [React Bits](https://reactbits.dev) provides animated components with source variants for different stacks.
- [Magic UI](https://github.com/magicuidesign/magicui) provides animated React components.
  Its repository has an [MIT license](https://github.com/magicuidesign/magicui/blob/main/LICENSE.md).

Check the current component source and license before adoption.
A public demo does not make every linked asset or paid variant open-source.
Prefer an existing project primitive or a CSS transition when it meets the same need.
